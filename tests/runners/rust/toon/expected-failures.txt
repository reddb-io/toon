# Official TOON spec fixtures this crate does not yet satisfy.
# Format: <decode|encode>/<fixture-file>.json::<test name>
#
# Fixtures are read live from the `vendor/toon-spec` submodule, so the corpus
# tracks upstream instead of drifting from a vendored copy.
#
# A decode case counts as passing only when all three hold: it parses, the
# decoded value equals the fixture's `expected` JSON, and our own canonical
# output decodes back to that same value. Parsing without an error is not
# enough — returning the wrong value silently is the failure mode that matters
# most, and it is invisible to an is_ok() check.
#
# This ledger is a ratchet, not a target: entries may only be removed.
#
# --- v4.1.1 renormalization baseline (Spec #203, issue #204) ---
#
# vendor/toon-spec is pinned at v4.1.1 (62f16b3). The renormalized v4 corpus
# introduces fixtures the current v3.3-era decoder/encoder does not yet
# satisfy. They are recorded here as an explicit expected-failure baseline —
# not skipped silently — so the pre-rebase gap is demonstrable and CI stays
# green until the decoder rewrites land. Each entry is removed as the
# corresponding v4 behavior is implemented (the ledger is a ratchet).

encode/objects-keyed.json::encodes an eligible root object with a keyless keyed header
encode/objects-keyed.json::collapses uniform nested object columns inside keyed headers
encode/objects-keyed.json::orders fields by the first entry value's encounter order
encode/objects-keyed.json::uses the active delimiter in keyed headers and entry-row cells
encode/objects-keyed.json::quotes entry keys per key encoding
encode/objects-keyed.json::quotes entry-row cells containing the active delimiter

# v4.1 comment-aware quoting is an encoder gap (#210): the legacy serializer

# as comment lines. Remove when the v4.1 Rust encoder lands.
