# Official TOON spec fixtures the JS implementation does not yet satisfy.
# Format: <decode|encode>/<fixture-file>.json::<test name>
#
# Fixtures are read live from the `vendor/toon-spec` submodule, so the corpus
# tracks upstream instead of drifting from a vendored copy.
#
# A decode case counts as passing only when it parses, the decoded value equals
# the fixture's `expected` JSON, and our own canonical output decodes back to
# that same value. Parsing without an error is not enough — returning the wrong
# value silently is the failure mode that matters most.
#
# This ledger is a ratchet, not a target: entries may only be removed.
#
# --- v4.1.1 renormalization baseline (Spec #203, issue #204) ---
#
# vendor/toon-spec is pinned at v4.1.1 (62f16b3). The renormalized v4 corpus
# introduces fixtures the current v3.3-era decoder/encoder does not yet
# satisfy. They are recorded here as an explicit expected-failure baseline —
# not skipped silently — so the pre-rebase gap is demonstrable and CI stays
# green until the decoder rewrites land. Each entry is removed as the
# corresponding v4 behavior is implemented (the ledger is a ratchet).
